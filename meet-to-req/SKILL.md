# Meet-to-Req: 会议纪要融合需求文档技能

**目标**：将沟通/评审会议纪要中的核心决策、架构分工、应急机制、T+1处理策略等要点，自然无缝地深度融合到需求 Markdown 文档的 `#### **评审纪要**` 中，提升需求文档的严密性与落地性。

---

## 核心融合原则

1. **事实优先，严禁虚构**：严格基于会议纪要和原需求文档的已知事实，不得臆测未讨论的技术点或系统规则。
2. **结构化呈现，自然流畅**：将会议中零散的讨论要点重构为有逻辑分类的结构化条目（如账户级与划转策略、日间调减与应急机制、T+1恢复策略等），避免流水账式的会议纪要复述。
3. **参会人员全量合并**：自动对齐并合并会议纪要与需求原有的参会人员名单，去除重复人名，补充部门归属。
4. **保留原增量公式与技术细节**：原需求中已有的细节（如 `MAX(变更后-变更前, 0)`、Task 编号等）必须精细保留并与新讨论结论融为一体。
5. **精炼简洁，专注决策**：评审纪要仅保留参会人员、核心决策要点、涉及系统和预计完成时间，不放入具体的待办事项清单。

---

## 融合处理流程

### Step 1: 读取与分析输入
- **会议纪要文件**：提取参会人员、背景动机、关键架构决策、应急/风险方案、简化妥协结论。
- **目标需求文件**：读取现有 `#### **评审纪要**` 及 `#### **三、技术实现**` 结构，识别已有的要点与系统范围。

### Step 2: 核心信息提取与分类映射

| 会议纪要信息块 | 融合目标位置 | 表达方式规范 |
| :--- | :--- | :--- |
| 会议发起人与参会部门 | `#### **评审纪要**` 导言句 | **自建会议**：`[YYYY年MM月DD日]经与**[部门A]**[人员1]和**[部门B]**[人员2]...沟通评审通过`<br>**他人/跨部门发起**：`[YYYY年MM月DD日]由**[发起部门/主持人]**发起，经与**[部门A]**[人员1]和**[部门B]**[人员2]...沟通评审通过` |
| 架构/推送/划拔策略 | 评审纪要核心要点第 1 条 | 明确增量推送节点（上海/深圳主节点）、发起主体（客户自主/系统自动） |
| 调减/风险/应急方案 | 评审纪要核心要点第 2 条 | 明确非推送场景原因（如防已用额度冲突）及手工应急调整菜单/工具配置 |
| T+1/持久化/清算规则 | 评审纪要核心要点第 3 条 | 明确是否持久化、日初恢复按策略划分规则及业务揭示责任 |
| 原已有划转/逻辑 | 评审纪要核心要点第 4 条 | 结合双节点自由划析与事务回滚机制整合输出 |
| 涉及系统范围更新 | `涉及系统：` | 补充会议中出现的相关交易、清算、信管等系统 |

### Step 3: 标准输出结构规范与多轮会议融合

在目标需求 Markdown 文档中，将 `#### **评审纪要**` 重构或增量融合为以下格式。**若该需求已存在早期评审纪要，按时间倒序/版本子标题增量融合，保留历史决策**：

```markdown
#### **评审纪要**
  YYYY年MM月DD日由**[发起部门/主持人]**发起（或“经与”），经与**[部门1]**[人员列表1]和**[部门2]**[人员列表2]沟通评审通过，核心决策及结论如下：

  1. **[核心要点1：额度同步与增量推送]**：集中清算系统与交易柜台实现账户级授信额度实时同步对接。日间调增授信额度时，清算侧直接将调增增量（Delta值 = MAX(变更后 - 变更前, 0)）推送到柜台主节点（上海节点），跨节点划拨由客户自主发起。
  2. **[核心要点2：日间调减与应急机制]**：日间调减仅在清算系统留存，不实时推送到交易柜台（防止与节点已用额度冲突）；柜台保留节点级授信额度手工调整菜单/工具，用于单侧划转失败等异常情况下的运维应急修正。
  3. **[核心要点3：T+1日持久化与划分恢复]**：暂不进行日间划拨数据的 T+1 日持久化。T+1 日初上场统一保持现有规则，按策略中心维护的可用额度比例重新划分上场；由业务部门负责向重点客户做业务揭示与告知。
  4. **[核心要点4：节点划转与事务一致性]**：柜台支持一户两地双节点间授信额度与可用额度的实时自由划转及事务回滚机制。

  涉及系统：[系统1]、[系统2]、[系统3]
  预计完成时间：计划 YYYY年MM月
```

## 增量更新执行指引

1. **读文件**：读取会议纪要 MD 和需求 MD。
2. **精确替换**：找到需求 MD 中的 `#### **评审纪要**` 章节到 `---` 或 `**相关链接**` 之前的内容，使用 `replace_file_content` 工具替换为融合后的标准结构。
3. **校验**：确保参会人员完整、核心决策结构化清晰、不包含临时待办事项。
