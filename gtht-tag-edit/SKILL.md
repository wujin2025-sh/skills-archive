# 国泰海通需求自定义标签修改技能 (gtht-tag-edit)

自动按对话指令或 `ba-to-dev` 产出的需求 Markdown 文档中的 `tags` 字段，在国泰海通科技平台（fintech.gtht.com.cn）中修改并更新需求的自定义标签。

> ⚡ **特性与性能**：
> - **单笔/史诗双维度定位**：支持单笔需求编号（`R26xxxxxxx`）与史诗编号（`E`/`PG` 开头，如 `PG202204-0261` 批量更新）；
> - **共享会话与凭据**：复用 `~/.config/gtht/config.json` 与 `~/.local/share/gtht/session.json`；
> - **自动格式化与去重**：自动处理多标签转换，支持逗号分隔。

## 🚀 三种主要使用模式

### 模式一：`ba-to-dev` 需求文档自动化联动（推荐）

当用户完成 `ba-to-dev` 需求分析并生成 Markdown 文档后，或用户说「修改需求标签」、「同步标签」时：

1. **自动定位需求文档**：优先读取当前对话或 `/Volumes/Macintosh HD_Data/obsidian/100_Projects/需求分析/` 目录下最新修改的需求 Markdown 文档。
2. **提取要素**：
   * **`req_id`**：读取 Front Matter `req_id: R26xxxxxxx` 或标题中的需求编号；
   * **`tags`**：读取 Front Matter 中的 `tags: [标签1, 标签2]` 列表（例如 `CX-使能B,CX-业务`）；
3. **业务领域标签自动推断规则**：
   * **两融业务**：若需求涉及「融资融券」、「两融」、「信用交易」、「信用两融」，自动追加标签 **`CX-信用-两融`**；
   * **股票质押**：若需求涉及「股票质押」、「股质」、「质押」，自动追加标签 **`CX-信用-质押`**。
4. **极速更新**：
   ```bash
   python3 "$SCRIPT" <req_id> --tags "<标签1,标签2>"
   ```

---

### 模式二：单笔需求命令行 / 对话修改

用户显式提供需求编号和自定义标签列表：

```bash
# 示例：为 R2608100032 设置自定义标签为 CX-使能B,CX-业务
python3 "$SCRIPT" R2608100032 --tags "CX-使能B,CX-业务"
```

---

### 模式三：按史诗编号批量修改下属需求标签（借鉴 `req-attr-edit`）

用户提供史诗编号（以 `E` 或 `PG` 开头，如 `PG202204-0261` 或 `E202204-001`），自动匹配大宽表热缓存并批量更新该史诗下属的所有需求与 Story 的自定义标签：

```bash
# 示例：为史诗 PG202204-0261 下属的所有需求批量设置标签
python3 "$SCRIPT" PG202204-0261 --tags "CX-道合大宗,CX-股期"
```

#### 参数说明表

| 参数 | 必填 | 格式与说明 | 默认值 |
|---|---|---|---|
| `<id_or_epic>` | **是** | 需求编号（`R26xxxxxxx`）或史诗编号（`E`/`PG` 开头，如 `PG202204-0261`） | - |
| `--tags` | **是** | 需求自定义标签，多个用逗号分隔，如 `CX-使能B,CX-业务` | - |
| `--dry-run` | 否 | 仅模拟校验，不实际提交落库 | `False` |
