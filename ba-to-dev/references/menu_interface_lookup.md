## 四、公共接口多菜单的筛选

一个公共接口（如 `11811004` 客户信息查询）可命中 100+ 菜单，此时脚本按"该菜单 ESB 调用数"降序展示前 N 个（`--top` 控制），并提示为公共接口。筛选方法：

1. **业务语义匹配**：菜单名与需求业务域直接相关的优先（如 QFII 需求命中列表里的「QFII客户个性化交易设置」）；
2. **正向核对**：用 `--menu <菜单名>` 查该菜单调用的接口号，确认目标接口号在其列中；
3. **结合改造范围**：只取本次评审纪要第 2 项改造范围内系统对应的菜单；
4. 仍无法唯一确定 → 第 4 项按最相关菜单填写并在评审决策日志标注"具体菜单以研发确认为准"，严禁编造功能号。

## 五、方向②：菜单 → 接口号（供第 5 项接口交互 / 后续检索）

需求常只写菜单名（如「改造【联合开户】菜单」），BA 要知道该菜单调用哪些接口号以便第 5 项核对或后续 fwzl-mcp 检索：

```bash
$P $S --menu 联合开户              # 出完整去重接口号清单：综合理财号(273)/外围号(98)/serviceId(305)，按类分组
$P $S --menu-extract "第二章原文"   # 从原文抽【菜单名】+ 功能号 NNNNN，批量反查 + 汇总接口号清单
```

**输出要点**：
- `--menu` 对唯一/少量命中出**完整去重接口号清单**（不再截断前 12 个），三类分列，末尾给 `--batch` 批量反查命令，可直接喂 fwzl-mcp / interface_query 做接口详情检索。
- `--menu-extract` 只对**唯一命中**的菜单自动汇总接口号（防泛词污染）；多命中（如「联合开户」匹配 9 个变体）只列候选、须 `--menu <精确名>` 收敛；未命中给体系提示。
- **P0#22 防望文生义**：脚本**不按「融资融券」这类泛词片段拆分匹配**（会误命中一堆不相干菜单）；「单户查询-融资融券-历史仓单资券变动」整体命中不到即判为另一体系，不硬凑。
