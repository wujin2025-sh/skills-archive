# to-do-req — Fintech 需求筛选工具

自动登录 fintech.gtht.com.cn 需求管理平台，筛选「我受理的」且状态为待受理、待拆分、技术评估、讨论中的需求。不限制 OA 状态以确保完整性，按状态优先级（待受理 -> 讨论中 -> 待拆分 -> 技术评估）分组排列，各组内部按照需求编号数值从小到大升序排序，并给出 Markdown 超链接结果输出。

## 触发条件

当用户提到以下关键词时使用本技能：
- to-do-req、待处理需求、待处理
- 我受理的需求筛选
- pending requirements、待办需求
- 查看我受理的未完成需求

## 使用方式

运行 `scripts/filter_demand.py` 脚本，该脚本自包含全部逻辑（登录态验证、下拉框 scope 切换、动态表单配置、数据抓取、后处理兜底过滤及排序格式化）。

```bash
cd "/Volumes/Macintosh HD_Data/WorkBuddy/需求管理" && \
  .venv/bin/python ~/.workbuddy/skills/to-do-req/scripts/filter_demand.py [可选参数]
```

可选参数：
- `--output`：输出文件路径，默认 `filter_results.md`
- `--headed`：是否以有界面模式运行（默认无界面运行以提高速度和免除干扰）
- `--browser`：选择浏览器引擎（默认 `firefox`，可选 `chromium`）
- `--cdp`：连接已运行 Chrome 的 CDP 调试地址（如 `http://localhost:9222`）

## 筛选逻辑

脚本执行步骤如下：
1. **会话校验**：访问 `DEMAND_URL` 并动态检测 `.selectInputStyle___3Nayz` 等特征元素。若会话有效则跳过登录（使用 `.fintech_session.json` 自动复用）；失效则重定向至登录页并自动输入工号密码提交登录。
2. **切换范围**：动态遍历查找并点击对应范围选择下拉框，如果当前选中的不是「我受理的」则切换为「我受理的」。
3. **清空残留**：遍历表单输入框并执行清空操作，防止由于历史编号残留导致搜索结果为空。
4. **展开面板**：动态探测“更多”面板的展开状态（若“已提交OA”标签不可见则试探点击按钮展开），避免盲目点击导致折叠。
5. **状态筛选**：使用 Placeholder 精准锁定状态下拉框，依次点击选择「待受理」「待拆分」「技术评估」「讨论中」，设置 2 秒短超时防卡死。
6. **数据检索**：收起面板，点击“查询”按钮并动态监听 Ant Design 滚动加载与 Loading 完毕状态。
7. **数据后处理与兜底过滤**：
   - 提取表格行内容。
   - 保留状态在 `待受理`、`待拆分`、`技术评估`、`讨论中` 范围内的记录。
   - 保留所有符合上述状态的目标需求，不论其 OA 状态为何（不再对 OA 状态为“已提交”的待拆分或技术评估等需求进行过滤，确保所有待办全部输出）。
8. **排序规则**：
   - 按状态优先级分组：**待受理** -> **讨论中** -> **待拆分** -> **技术评估**。
   - 组内成员按需求编号升序（从小到大）排列。
9. **格式输出**：对列表中的需求编号加上 Markdown 点击链接，同时生成 `filter_results.md` 并打印至控制台。

## 环境依赖

- Python 虚拟环境：`.venv/`（项目根目录，包含 playwright 依赖包）
- Playwright Firefox 浏览器引擎（原生支持无界面 headless 运行，且避开了 macOS 沙箱对 Chromium 的限制）

## 注意事项

- **极速响应**：脚本默认在 headless 无界面模式运行，不弹窗，配合秒级 Session 免登复用和 2 秒短超时快速失败设计，整体运行时间能控制在 15s 左右。
- **降级保护**：当 UI 交互（例如状态或 OA 下拉框）偶发加载延迟时，2 秒超时会自动跳过并打印异常，随后完全依赖 Python 在提取出表格数据后进行高可靠的后处理集合过滤，依然保证最终输出的 100% 准确性。
