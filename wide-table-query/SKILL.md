# 大宽表查询

## Overview

打开金融科技平台「交易结算核心系统需求集合」在线表格页面，将用户在对话框中输入的搜索关键字填入页面搜索框，触发 AG Grid Quick Filter，然后通过导出 Excel 获取过滤后的数据，提取关键字段并格式化输出。

## When to Use

- 用户提供搜索关键字（需求编号如 PG202204-0155、需求名称关键词如"融资融券"、系统名等），要求在交易结算核心系统需求集合中搜索
- 触发词：大宽表、宽表查询、搜索需求、查需求集合

## Usage

执行脚本，传入搜索关键字作为参数：

```bash
.venv/bin/python scripts/wide_table_query.py <搜索关键字> [--headed] [--output result.md] [--html]
```

### 参数说明

- **搜索关键字**（必填）：需求编号（PG202204-0155）、需求名称关键词（融资融券）、系统名等
- `--headed`：显示浏览器窗口（调试用）
- `--output` / `-o`：输出 Markdown 文件路径（默认自动生成到 downloads/ 目录）
- `--html`：同时生成 HTML 可视化文件（卡片布局，含状态色标）
- `--fresh`：强制从服务器获取最新数据，不使用本地缓存

### 环境要求

- Python 虚拟环境 `.venv/` 中需安装 `playwright`、`openpyxl`
- Playwright Chromium 已安装
- 脚本默认 headless 模式运行（不显示浏览器窗口）
- Session 文件 `.fintech_session.json` 位于项目根目录，多个 fintech 脚本共用

### Session 复用

- 脚本启动时自动加载已有 session（`.fintech_session.json`）
- 先尝试直接访问表格页，若未被重定向到登录页则跳过登录
- 仅在 session 失效时才执行登录并保存新 session
- 脚本结束时再次保存 session，保持最新登录态

### 缓存与高速 API 机制

为了应对 14,000+ 行（约 30.8 MB JSON 数据）的服务器端加载与网络传输延迟，脚本实现了一套高速 API 与本地缓存机制：

1. **高速 API 查询 (Layer 1 & 2)**：直接调用后端 API `getSheetContent` 发起 HTTP 请求进行内存处理，完全省去了 Playwright 的浏览器启动和页面渲染开销。
2. **本地 JSON 缓存**：成功拉取全量数据后，将缓存在 `downloads/.sheet_cache.json` 中。
3. **缓存时效管理**：缓存有效期限为 **5分钟**。在 5 分钟内执行任何关键字查询，脚本将在 **1秒左右** 瞬间完成检索与 Excel/Markdown/HTML 的重新输出，无需等待后端数据库加载。
4. **缓存强制刷新**：通过追加 `--fresh` 参数，强制穿透本地缓存重新从线上拉取最新数据。

### 工作流程

1. **直接 API 高速获取 (Layer 1)**: 优先读取本地 session 中的 cookies 和 `GTJA_TOKEN`（作为 HTTP `token` 头），直接向后端大宽表数据接口发起 HTTP 请求，在本地内存中对全量数据行进行关键词匹配，并以 10 个关键字段保存至兼容性 Excel 备份 (平均耗时 2-3s)。
2. **浏览器登录 + 接口获取 (Layer 2)**: 如果 session 缺失或接口返回 401 鉴权失效，自动启动 Playwright 浏览器以 headed/headless 模式执行登录，提取最新 token 与 Cookie，并重新发起 API 数据查询并保存 (耗时 10-15s)。
3. **传统物理导出兜底 (Layer 3)**: 若上述接口路径均报错，退回使用传统物理导出路径。利用 Playwright 操作 AG Grid 搜索框、等待表格稳定、点击「导出 -> 导出excel」物理下载文件 (耗时 30-40s)。
4. **格式化输出**：按需提取并进行多端展示：对话窗口列对齐版文本表，Markdown 文件版详情，以及通过命令行参数 `--html` 产生的卡片可视化形式。
5. **用户响应与卡片可视化**：默认情况下优先呈现纯文本以便超高速加载；当用户指令中含有“可视化”时才使用 `show_widget` 打开交互式卡片面板。

### 输出格式

**对话窗口**：列对齐精简表格，包含序号、需求编号、需求名称、Story系统、Story状态、验收结果、生产排期、版本排期，末尾附备注

**Markdown 文件**：按需求分组，含需求详情页链接（`/kjpt/DemandManage/details?demandId=XXX`）、史诗编号、各系统行的完整元数据

**HTML 可视化**（`--html`）：卡片布局，顶部指标概览（需求数/记录数/验收通过/排期），每个需求一张卡片含系统标签和状态色标（绿=通过、橙=测试中、红=待验收），底部备注提示条。可用 `preview_url` 在对话窗口内展示。

### 输出文件

- `downloads/exported_<关键字>.xlsx` — 导出的 Excel 原始文件
- `downloads/result_<关键字>.md` — 格式化后的 Markdown 结果
- `downloads/result_<关键字>.html` — HTML 可视化（仅 `--html` 时生成）
- 若指定 `--output`，额外写入一份 MD 到指定路径

## 对话窗口卡片渲染（按需触发）

**默认不渲染**，先输出文本结果以节省响应时间。仅当用户在对话窗口输入「可视化」时，才用 `show_widget` 渲染卡片。

### 触发条件

- 用户输入包含「可视化」关键字时触发
- 渲染时使用最近一次查询的 Markdown 结果文件（读取 `downloads/result_<最近关键字>.md`）

### 渲染步骤

1. 确认上下文中已有最近一次查询的关键字和结果文件路径
2. `read_me(modules=["interactive"])` 加载设计系统
3. 读取 Markdown 结果文件，提取结构化数据（需求数、记录数、各需求名称/编号/系统/状态/备注）
4. 用 `show_widget` 渲染 HTML 卡片

### 卡片结构

从上到下依次为：

1. **头部**：蓝色圆形图标 + 标题「交易结算核心系统需求集合」+ 副标题「<关键字> · <史诗名称>」
2. **4 个指标卡**（grid 4 列）：需求数、系统记录数、验收通过率（绿色数字）、排期日期
3. **需求卡片**（每需求一张，白色圆角卡片）：
   - 第一行：需求名称（左）+ 需求编号可点击链接（右，蓝色，跳转详情页）
   - 每个系统一行：蓝色系统标签（`#B5D4F4` 背景 `#0C447C` 文字）+ 测试状态（灰色文字）+ 验收结果（色标 badge）
4. **备注提示条**（若有备注）：黄色背景 `#FAEEDA` + 警告图标 + 文字
5. **底部**：居中灰色小字「共 X 个需求、Y 条记录 | 搜索：<关键字>」

### 色标规则

| 状态 | 背景色 | 文字色 | 说明 |
|------|--------|--------|------|
| 业务验收通过 | `#EAF3DE` | `#3B6D11` | 绿色 badge |
| 待业务验收 | `#E1F5EE` | `#0F6E56` | 青绿 badge |
| UAT自测中 | `#FAEEDA` | `#854F0B` | 橙色 badge |
| 待排期/待UAT自测 | 灰色文字，无 badge | `var(--color-text-tertiary)` | 仅文字 |

### 约束

- 使用 CSS 变量（`var(--color-xxx)`），不硬编码颜色（系统标签和状态 badge 除外）
- `sr-only` 的 `<h2>` 包含一句话摘要，用于无障碍
- 需求编号链接格式：`https://fintech.gtht.com.cn/kjpt/DemandManage/details?demandId=<编号>`
- loading_messages 用中文：`["解析查询数据", "构建卡片布局", "应用状态样式", "渲染完成"]`

## 注意事项

- AG Grid 搜索框 `#filter-text-box` 会自动清空，搜索→导出必须在 7 秒内完成（当前流程约 4 秒）
- 导出按钮是两步交互：主按钮打开 ant-popover → popover 内「导出excel」触发下载
- 导出的是过滤后的数据（非全量），Excel 文件通常 < 1MB
- 多次运行同一脚本 session 会复用，不会重复登录
- `--headed` 参数仅用于调试，生产环境使用默认 headless 模式
