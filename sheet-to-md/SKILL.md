# sheet-to-md — 腾讯文档 Sheet → Obsidian MD 反写

## 功能

从腾讯文档在线表格（默认第一个 Sheet）读取需求记录，按需求名称匹配本地 MD 文件，将在线文档中的列数据反写到 MD 对应章节。

**v7 更新**：
- **K列 (备注) 智能融合** — 备注（K）融入 `三、技术实现` 与 `评审纪要` 的内容中。若原有内容与备注有冲突，以备注为准，确保句式通顺、表达专业且易于理解。
- **G列 (关联系统) 位置调整** — 关联系统（G）从 `三、技术实现` 中移出，放入 `评审纪要` 的 `涉及系统：xxx` 行的正下方。
- **临时标记机制** — 脚本在检测到备注更新时，以 `<!-- REMARK_START -->\n备注：...\n<!-- REMARK_END -->` 的临时 HTML 注释将备注插入到对应章节，待 AI 助手通过大语言模型进行句意融合与润色，并清理该临时注释。
- **增量比对更新** — 比对所有相关属性，如无新变化不重复修改文件。
- **智能核心词匹配 (LCS)** — 弃用纯标签匹配，通过去除系统前缀、括号和 stop words 后的最长公共子序列 (LCS) 与字符重合度打分，支持模糊名称和带括号等样式的前缀自动映射，防范跨文件错配。
- **文件最后修改时间作为评审时间 (mtime)** — 自动提取本地文件在磁盘上的最后修改时间 (mtime) 写入「评审纪要」，保留评审通过时效的真实性。
- **评审纪要列表解析、位置防御与风格自适应** — 使用通用正则兼容无粗体标题的原始列表项；且在无列表条目时将备注自动插入到评审通过行下方。新增列表项时，会自动检测并适配现有列表项的标题样式（若现有为无加粗标题风格，则新增项亦保持无加粗标题），并且将备注中的换行符替换为分号展示在单行内，确保全局排版风格高度一致。

## 数据映射

| 在线文档列 | MD 目标章节 | 写入方式 |
|:---|:---|:---|
| F — 涉及系统 | 评审纪要 | `涉及系统：xxx`（预计完成时间上方） |
| G — 关联系统 | 评审纪要 | `关联系统：xxx`（放在 `涉及系统` 下方） |
| H — 计划排期 | 评审纪要 | `预计完成时间：计划 xxx` |
| K — 备注 | 三、技术实现 和 评审纪要 | 插入临时备注标签后由 AI 助手语义融合成专业、通顺内容 |
| L — 参会人员 | 评审纪要（第一句） | `YYYY年MM月DD日经与**部门A**人员A和**部门B**人员B沟通评审通过` |

```bash
python3 ~/.codex/skills/sheet-to-md/scripts/sheet_to_md.py gpzy --apply

# 反写其他需求表格 (qt)
# 访问：https://docs.qq.com/sheet/DVE9Gb0daTmtzUE9H?tab=BB08J2 (其他需求跟踪)
python3 ~/.codex/skills/sheet-to-md/scripts/sheet_to_md.py qt --apply

# 预览模式 (仅比对并输出差异预览，不实际修改本地 MD)

# 自定义 CSV 文件路径

```

## 评审纪要完整格式

```
#### **评审纪要**

YYYY年MM月DD日经与**部门A**人员A和**部门B**人员B沟通评审通过

1. **集中交易系统切换**：切换参数源...
2. **集中清算系统切换**：切换参数源...
3. **一致性核验**：确保字段一致性...
4. **生产数据核对**：核对集中交易跟参数中心S02生产差异项。（备注智能融入现有条目）

涉及系统：集中交易、集中清算、参数中心
关联系统：参数中心已切换
预计完成时间：计划 8月份
```

**关键顺序**：参会人员第一句 → 编号评审要点（备注语义融入） → 涉及系统 → 关联系统 → 预计完成时间

## K列 (备注) 语义融合与冲突解决规则

大语言模型（AI 助手）在执行此技能时，需要对临时标志包裹的备注（K）进行语义融合与冲突处理：

1. **评审纪要融入**：
   * 优先匹配并融入现有编号条目（如包含相关系统、模块或规则）。融入时需重写合并后的描述，使句式专业、语言通顺。
   * 若备注中提供的值/规则与原 MD 内容有冲突，**以备注为准**，修改并覆盖原句的冲突表述。
   * 若完全属于新内容且无法合并到已有条目，则新增编号条目，自拟简短的加粗标题。
2. **技术实现融入**：
   * 将备注内容自然融入 `三、技术实现` 中对应的技术分支或核心计算规则中。
   * 若已有实现规则或公式与备注冲突，**以备注为准**，直接覆写原有的公式或文字描述。
3. **清理标记**：
   * 融合完毕后，**必须**将所有的 `<!-- REMARK_START -->` 和 `<!-- REMARK_END -->` 及其所包裹的临时原始文本彻底删除。

## 过滤规则

| 条件 | 处理 |
|:---|:---|
| J列 = `通过` 或 `评审通过` | 处理 |
| J列 = `待评审` / 空 / 其他 | 跳过，输出 ⏭️ |
| MD 中已有相同值 | 跳过，输出「内容已是最新」 |
| MD 文件不存在 | 输出 ⚠️ no_match |

## L列 部门解析规则

| L列格式 | 输出格式（示例） |
|:---|:---|
| `杜伟毅\n吴进\n厉凌杰\n许曼莉`（无部门前缀） | `**融资融券部**杜伟毅和**技术研发部**吴进、厉凌杰、许曼莉` |
| `融资融券部-杜伟毅`（含部门前缀） | `**融资融券部**杜伟毅` |
| `融资融券部-张三、营运部-李四`（多部门） | `**融资融券部**张三和**营运部**李四` |
| 空 | 保持原 MD 第一句不变 |
| 查不到部门 | 保留 `[部门名称A]` 占位 |

**格式规则**：
- 每个部门独立 `**加粗**`，后紧跟（无冒号）人员名
- 两个部门用 `和` 串联，三个及以上用 `、` 串联，最后两组间用 `和`
- 同部门多人用 `、` 分隔
