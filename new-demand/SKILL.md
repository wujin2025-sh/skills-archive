# New Demand（新建需求）

## Overview

将用户输入的需求描述转换为科技平台需求提报的标准结构。输入为一段描述文本，输出为规范化的需求文档，包含"一、需求背景"、"二、需求内容"及要素字段（涉及改造系统、开发人员、识别阶段、计划交付时间）。

## 工作流程

1. **接收描述**：接收用户输入的需求描述文本。
2. **拆分背景与内容**：
   - 若描述已明确区分"背景"与"内容"，直接对应填入；
   - 若为连续描述，按"原因/问题"与"改造动作"拆分为两部分。
3. **提取要素字段**：从描述中提取"涉及改造系统"、"开发人员"、"识别阶段"、"计划交付时间"；缺失的字段采用默认值（涉及改造系统=集中交易、识别阶段=生产、计划交付时间=当日），开发人员无默认值则留空。
4. **按模板输出**：严格遵循标准输出格式生成需求文本。

## 输出格式

完整格式模板、字段填写说明、处理规则与示例见 [output-format.md](references/output-format.md)。

核心输出结构：

```
一、需求背景
[背景描述]

二、需求内容
[内容描述]

 

涉及改造系统：[系统]

开发人员：[姓名]

识别阶段：[阶段]

计划交付时间：[日期]
```

## 关键规则

- **原文保留**：背景与内容尽量保留用户原意，不做过度润色，确保业务口径不失真。
- **字段默认值**：涉及改造系统、开发人员、识别阶段、计划交付时间若用户未提供，采用默认值：
  - **涉及改造系统**：默认 `集中交易`；
  - **识别阶段**：默认 `生产`；
  - **计划交付时间**：默认 `当日`；
  - **开发人员**：无默认值，保留字段名留空并提示用户补充。
- **格式严格**：严格遵循模板的空行与字段顺序，`涉及改造系统` 前保留一个空行。
