# 新建需求输出格式参考

将用户输入的需求描述转换为以下标准化结构，用于科技平台需求提报。

## 标准输出模板

```
一、需求背景
[需求背景描述：说明需求产生的业务背景、问题根源、触发场景]

二、需求内容
[需求内容描述：说明本次需求的具体改造内容与目标]

 

涉及改造系统：[改造系统名称]

开发人员：[开发人员姓名]

识别阶段：[识别阶段，如：生产/测试/开发]

计划交付时间：[YYYY-M-D 或 YYYY-MM-DD]
```

## 字段填写说明

| 字段 | 说明 | 来源 |
| :--- | :--- | :--- |
| **一、需求背景** | 需求产生的业务背景、问题根源、触发场景 | 从用户描述中提取背景部分；若描述未区分，则提炼问题起因 |
| **二、需求内容** | 本次需求的具体改造内容与目标 | 从用户描述中提取内容部分；若描述未区分，则提炼改造动作 |
| **涉及改造系统** | 需要改造的系统名称（如：集中交易、集中清算、低延时交易系统等） | 用户描述中明确给出；未给出时**默认"集中交易"** |
| **开发人员** | 负责开发的开发人员姓名 | 用户描述中明确给出；未给出时留空待填 |
| **识别阶段** | 问题识别阶段（生产/测试/开发） | 用户描述中明确给出；未给出时默认"生产" |
| **计划交付时间** | 计划交付日期（格式 `YYYY-M-D`） | 用户描述中明确给出；未给出时**默认"当日"** |

## 处理规则

1. **背景与内容拆分**：若用户描述已包含"背景"和"内容"两部分，直接对应填入；若为一段连续描述，按"原因/问题"与"改造动作"拆分为两部分。
2. **原文保留**：背景与内容尽量保留用户原意，不做过度润色，确保业务口径不失真。
3. **字段缺失处理**：涉及改造系统、开发人员、识别阶段、计划交付时间若用户未提供，采用默认值：
   - **涉及改造系统**：默认 `集中交易`；
   - **识别阶段**：默认 `生产`；
   - **计划交付时间**：默认 `当日`；
   - **开发人员**：无默认值，保留字段名留空并提示用户补充。
4. **格式严格**：输出严格遵循标准模板的空行与字段顺序，`涉及改造系统` 前保留一个空行。

## 示例

**输入描述**：
> 0807版本上线需求：客户资产口径（股权激励行权摘要调整）部分场景修复，将股权激励行权冻结资金和股权激励税费冻结资金，交易系统的记录由 "在途买入"调整为买入冻结。导致现金管家现金宝扫单时没有将这部分资金计算到赎回因子中，之前记录在"在途买入"字段时会计算到赎回因子。现金管家现金宝扫单时，通过读取集中清算给的股权激励行权冻结资金和股权激励税费冻结资金冻结的资金科目，计算到赎回因子中。涉及改造系统：集中交易。开发人员：厉凌杰。识别阶段：生产。计划交付时间：2026-8-31。

**标准输出**：
```
一、需求背景
0807版本上线需求：客户资产口径（股权激励行权摘要调整）部分场景修复，将股权激励行权冻结资金和股权激励税费冻结资金，交易系统的记录由 "在途买入"调整为买入冻结。导致现金管家现金宝扫单时没有将这部分资金计算到赎回因子中，之前记录在"在途买入"字段时会计算到赎回因子。

二、需求内容
现金管家现金宝扫单时，通过读取集中清算给的股权激励行权冻结资金和股权激励税费冻结资金冻结的资金科目，计算到赎回因子中。

 

涉及改造系统：集中交易

开发人员：厉凌杰

识别阶段：生产

计划交付时间：2026-8-31
```
