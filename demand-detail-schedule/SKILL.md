# 需求明细进度监控与环节提醒工具 (demand-detail-schedule)

> [!NOTE]
> **技能定位**：本 Skill 用于自动监控需求在 **💻 开发相关**、**🧪 SIT 测试**、**🔍 UAT 自测** 各个环节的明细进度，识别评估预计时间与真实实际完成时间，计算环节 **「逾期 N 天」** 标注，并一键生成自包含高颜值 HTML 动态报告。

---

## 🎯 触发词与 3 大核心模式

当用户提到 “需求明细进度”、“明细风险表”、“排期进度表”、“吴进最新排期明细”、“排期20260807” 或直接输入排期/姓名/需求编号时触发：

| 模式 | 触发场景/输入示例 | 筛选规则与计算动作 | 导出 HTML 文件名规则 | 【计划生产排期】列 | 页面列数 |
| :---: | :--- | :--- | :--- | :---: | :---: |
| **模式 1** | `20260807` | **全量排期版本筛选**：输出该排期版本下的所有逾期与预警需求明细 | `需求明细风险提醒表20260807.html` | 隐藏 | **20 列** |
| **模式 2** | `20260807 吴进` | **排期 + 受理人筛选**：输出指定受理人在该排期版本的逾期与预警需求明细 | `需求明细风险提醒表20260807-吴进.html` | 隐藏 | **20 列** |
| **模式 3** | `吴进` | **姓名跨版本筛选**：自动检索 $\ge$ 当前日期的最近 3 个排期版本（由小到大升序），合并 3 个版本的风险记录至单个文件 | `需求明细风险提醒表<当前输出日期>-吴进.html`<br>*(例: `需求明细风险提醒表20260727-吴进.html`)* | **保留 (Col 1)** | **21 列** |

## ⚙️ 核心数据处理与计算规则

1. **阶段标准状态规范 (彻底废除“正常”模糊统称)**：
   - **开发 (Dev)**：严格限定为 `已完成` (显示 `✅ 已完成`) | `待开发` | `开发中` | `待排期`
   - **SIT / UAT**：严格限定为 `已完成` (显示 `✅ 已完成`) | `待自测` | `自测中` | `自测待排期` | `--` (未开启)
2. **权威【计划生产排期】匹配 (`planProdLineDate`)**：
   - 严格精准匹配大宽表中权威的 **`planProdLineDate`**，隔离 Story 内部迭代编码干扰，确保需求版本归属百分百精准。
3. **【预计结束时间】各阶段提取法则**：
   - **开发相关**：**预计结束** 严格取自 **Story 详情 -> 评估 / 基本信息 : 开发预计结束时间**（`devAssessDateEnd` / `storyItDuedate`）。
   - **SIT 测试**：**预计结束** 严格取自 **Story 详情 -> 评估 / 测试信息 : SIT测试预计结束时间**（`sitTestAssessDateEnd` / `testAssessDateEnd`）。
   - **UAT 自测**：**预计结束** 严格取自 **Story 详情 -> 评估 / 测试信息 : UAT自测预计结束时间**（`uatTestAssessDateEnd`）。
4. **真实【实际结束时间】提取通用法则（严格取自 Story 一生）**：
   - **开发相关**：**实际结束** 严格取自 **Story 一生 : 开发实际结束时间**（`devFactEndDate` / `devActualDate` / `devFinishTime`）。
   - **SIT 测试**：**实际结束** 严格取自 **Story 一生 : SIT自测实际结束时间**（`sitFactEndDate` / `sitActualDate` / `sitFinishTime`）。
   - **UAT 自测**：**实际结束** 严格取自 **Story 一生 : UAT自测实际结束时间**（`uatFactEndDate` / `uatActualDate` / `uatFinishTime`）。
   - **绝对约束法则**：
     1. 若平台 `Story 一生` 中对应环节尚未生成或单独录入实际完成时间，一律真实如实展示为 `--`，绝对禁止借用预计结束时间假冒兜底！
     2. 绝不使用版本计划发布/上线交付日期（如 `largeDeliverDate` / `smallDeliverDate` / `planProdLineDate`）作为阶段实际完成时间。
     3. 绝不跨阶段互相挪用预计或实际完成时间。
4. **Story 详情核心字段提取通用准则**：
   - **原始需求提出人**：严格取自平台 **Story 详情 -> 基本信息 : 原始需求提出人**（`originalRequester`），隔离平台需求经办人干扰。
   - **业务验收人**：严格取自平台 **Story 详情 -> 业务与设计 : 业务验收人**（`businessAcceptor` / `storyBusAcceptor`）。
   - **验收状态**：严格取自平台 **Story 详情 -> 业务与设计 : 业务验收结果**（`storyBusName` / `storyResult` / `isHaveBus` -> `无需业务验收` \| `待业务验收` \| `已验收`）。
5. **【逾期 N 天】小字智能标注 (开发、SIT、UAT 各阶段独立优化)**：
   - 针对 **开发相关**、**SIT 测试**、**UAT 自测** 各自阶段独立计算。仅当该阶段存在 **`实际结束时间`** 且 **`实际结束时间 > 预计结束时间`** 时，在对应标准状态徽章下方展示红字提醒：**`逾期N天`**（计算公式：`逾期天数 = 实际结束 - 预计结束`）。
   - 若未录入/无实际结束时间（环节推进中），或 `实际结束时间 <= 预计结束时间`（按期或提前完成），一律**不展示逾期天数**。
6. **【全完成记录】彻底过滤**：
   - 若某一 Story 的 **【开发相关】**、**【SIT 测试】**、**【UAT 自测】** 三个环节的状态 **均为 `✅ 已完成`**（表示研发测试全流程已结束），自动从风险提醒报告中彻底过滤排除，仅保留仍存在活跃风险的项目。

## 💻 智能体命令行调用说明 (CLI Guide)

智能体在执行终端命令时，可直接通过 `python` 调用内部脚本：

```bash
# 1. 姓名单维度查询（自动检索 >= 当前日期最近3个版本，合并输出，Col 1 含排期列）
python scripts/detail_schedule_generate.py 吴进

# 2. 排期 + 受理人组合查询（精简 20 列版，无排期列）
python scripts/detail_schedule_generate.py 20260807 吴进

# 3. 全量排期版本查询（精简 20 列版，无排期列）
python scripts/detail_schedule_generate.py 20260807

# 4. 指定需求编号查询
python scripts/detail_schedule_generate.py R2604300028
```
