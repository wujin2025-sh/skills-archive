# 史诗统计（epic-statistics）

## 概述

输入史诗编号（如 `PG202204-0236`、`E26xxxx`），统计该史诗下：
- **需求数量**（按需求编号去重）与 Story 记录数
- **涉及系统清单**及每个系统涉及的需求数（系统分布）
- **Story 状态分布**（结束/终止/开发中/SIT/UAT 等）
- **需求明细表**（需求编号、标题、涉及系统、Story 状态）

数据源为「交易结算核心系统需求集合」大宽表：通过 `wide-table-query` 技能脚本导出史诗过滤 Excel，再由本技能统计脚本读取计算。

## 使用方式

运行统计脚本（从技能 scripts 目录）：

```bash
python3 scripts/epic_stats.py <史诗编号>
```

常用参数：

| 参数 | 说明 |
|------|------|
| `--fresh` | 强制重新从大宽表导出（默认复用 1 小时内缓存 Excel，秒级返回） |
| `--system <名称>` | 仅统计涉及指定系统的需求 |
| `--status <状态>` | 仅统计指定 Story 状态的需求 |
| `--json` | JSON 结构化输出（供程序消费） |
| `--output <file.md>` | 同时将 Markdown 报告写入指定文件 |
| `--narrative` | 生成季度述职内容稿（对齐示例格式，见下文「述职内容生成模式」） |

示例：

```bash
python3 scripts/epic_stats.py PG202204-0236
python3 scripts/epic_stats.py PG202204-0236 --system 集中清算系统
python3 scripts/epic_stats.py PG202204-0236 --status 结束 --json
python3 scripts/epic_stats.py G202204-0236 --narrative   # G 开头自动补 P 容错
```

执行后按脚本输出的 Markdown 报告向用户呈现统计结果（需求数量、系统分布、状态分布、明细表）。

## 述职内容生成模式（--narrative）

**触发场景**：用户提供史诗编号并要求生成季度述职/述职内容稿/专项内容提取/PPT 素材（如「根据史诗 XX 生成季度述职内容」）。

```bash
python3 scripts/epic_stats.py <史诗编号> --narrative
# 史诗编号容错：G202204-0236 会自动补 P → PG202204-0236
```

**输出为双段结构，对齐示例格式且不千篇一律**：

1. **完整叙述版（供述职讲稿，范文式四段结构）**：
   - **引言（目的句 + 主线句 + 升华收尾）**：`为{目的A}、{目的B}，并为{目的C}，三季度我们重点推进了{主线}：{动作分解}，从根上卸下{系统}冗余负荷、理清{外围}依赖，为{未来演进}清理{耦合}。`（目的句与升华句来自场景 `intro`/`bg` 字段，自动数字化主线）；
   - **（一）需求承接无缝衔接，{N}个需求覆盖{M}个系统业务无感**：牵头承接内容 + 累计承接 N 个需求、覆盖 M 个系统（**精选系统清单**：清洗 (虚拟)/(Y公司) 等脏后缀 + 按涉及需求数降序取前 8 个 +「等」，附注区保留全量）；零中断尾句来自场景 `outro1`；
   - **（二）主动破局协同提效，{场景量化亮点}**：困难点 +「**机制**」+ 推动各系统明确排期配合联调 + 形成{主系统、清算侧、周边系统}三方协同（`p2_mode`）的跨团队模式；
   - **（三）统筹协调全局梳理，{场景量化亮点}**：基线梳理 + 自动填充已结束/上线需求数及占比、推进中数量；
   - **后续收尾**：推进中前 3 个需求简述，或场景收尾句（如迁移类「集中交易逐步暂停历史数据服务，集中清算不再上场集中交易历史数据」）；
   - 稿尾附「自动提取数据附注」仅供核对，勿写入述职正文。
2. **核心专项 PPT 素材版（可拆页）**：`▍专项主线/▍一句背景/▍亮点数据/▍承接需求（按主题归纳）/▍覆盖系统/▍推进状态/▍后续` 每块可独立作为一页素材直接使用。

**输出规则**：
- **基于史诗真实需求自动生成，小标题量化亮点自动嵌入**：小节标题固定为「（一）需求承接无缝衔接，{N}个需求覆盖{M}个系统业务无感」（数字自动填充）+「（二）…，{场景 th2}」+「（三）…，{场景 th3}」（场景量化短语），杜绝千篇一律模板句；
- **场景识别**：「主题互斥归组最大组优先 + 关键词加权评分兜底」（THEME_GROUPS 首命中互斥归组，经 THEME_SCENARIO 映射到 4 个具名场景：历史数据迁移 / 融资融券优化 / 清算结算改造 / 接口文件服务；无命中回落「专项能力建设」通用场景并附需求关键词提示主线）——主题互斥归组比词频更抗「接口/文件」等泛化词污染；
- **统计数字自动填充**（需求数、系统数、Story 数、状态占比、系统清单、推进中明细），直接可用；
- **系统清单清洗与精选**：正文系统名自动去除 `(虚拟)/(Y公司)/(临时)/(新)` 等环境标注脏后缀、按涉及需求数降序取前 8 个 +「等」（与范文「13个需求覆盖16个系统（…等）」一致），附注区保留全量原始清单供核对；
- **季度自动识别**（当前月份 → 一/二/三/四季度），无需手改；
- **业务叙述以【…】占位**（人工可校准细节等无法从史诗统计推导的内容），须人工校准后使用，严禁带【】交付；附注区注明「场景识别」与「主线关键词」便于人工核对；
- 推进中需求明细（编号+标题）放附注区，正文只保留数量与前 3 个简述，保证述职稿叙述干净；
- PPT 素材版末尾注明「数据为自动提取，业务叙述请按专项实际复核后使用」。

**与普通统计模式的区别**：`--narrative` 输出述职叙述（数据自动填充 + 占位校准），普通模式输出统计报告（Markdown/JSON），两者独立互不干扰。

## 依赖与数据流

```
epic_stats.py
  ├─ (缓存命中) downloads/exported_<史诗编号>.xlsx   # wide-table-query 技能产物，1h 内复用
  └─ (缓存未命中) subprocess 调用 wide-table-query/scripts/wide_table_query.py <史诗编号>
        └─ 浏览器物理导出 → downloads/exported_<史诗编号>.xlsx
  → openpyxl 读取 → 按「史诗编号」列过滤 → 统计输出
```

- 依赖 **wide-table-query 技能**已安装（`.chat/skills/wide-table-query/` 或 `.workbuddy/skills/wide-table-query/`），脚本自动探测两处路径；
- 系统 `python3` 需已安装 `openpyxl`（统计）与 `playwright`（导出时）；
- 导出走浏览器物理导出约 25~40s，命中缓存秒级返回，因此**优先复用缓存，仅数据变化或需最新时用 `--fresh`**。

## 注意事项

1. **大宽表脚本自身"有效匹配 0 行"是已知缺陷**：`wide_table_query.py` 的对话输出会误报"无匹配结果"，但其导出的 `exported_<史诗>.xlsx` 数据是完整的。本技能**直接读 Excel 统计，不依赖其对话输出**，不要因该提示误判无数据。
2. 导出文件保存在 `wide-table-query/scripts/downloads/exported_<史诗编号>.xlsx`；重复查询同编号会命中缓存。
3. 同一需求可能有多条 Story 记录（多系统/配合测试），需求编号去重后才计入"需求数量"；`需求数量` 与 `记录数量` 含义不同，汇报时勿混淆。
4. Story 标题为空的记录（需求已终止等场景）显示为「（标题为空）」，属正常现象。
5. 大宽表为**交易结算核心系统需求集合**，仅覆盖该集合内的史诗；查询结果为空时提示用户该史诗可能不在集合内或编号有误。
